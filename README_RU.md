## Установка

Откройте `olg_experiments_fex18593` как текущую папку MATLAB. Добавляйте только корень, без `genpath`:

```matlab
addpath(pwd, '-begin');
which olg_config -all
which run_olg_experiment -all
```

Проверка выполняется в MATLAB R2024a. Для параллельного поиска нужен Parallel Computing Toolbox. Последовательный поиск и сравнение индикаторов работают в базовом MATLAB.

Дополнительные C++ MEX-ядра поставляются исходниками. Для своей платформы соберите их установленным компилятором MATLAB:

```matlab
build_olg_fast
```

**После обновления с 24 октября пересоберите MEX:** интегратор теперь возвращает сведения по каждому узлу. Перед сборкой завершите расчёты и закройте прежний pool, чтобы workers загрузили новую библиотеку. Без компилятора используйте MATLAB-интегратор, MATLAB FFT и `cfg.rosenstein.neighborMethod='brute'`. По умолчанию первые два компонента уже MATLAB; поиск соседей автоматически использует дерево, если оно собрано.

## Эксперимент 1

```matlab
cfg = olg_config('compare_DE_vs_full_scan', 'paper');
result = run_olg_experiment(cfg);
```

**По умолчанию `cfg.search.gridMode='estimate'` переносит постановку свежего fast-архива:** пять реальных запусков DE, измеренные пробы сетки и две экстраполяции её стоимости. Это не завершённый восходящий поиск.

Для реального сравнения DE и полного восходящего перебора выберите:

```matlab
cfg.search.gridMode = 'full_scan';
cfg.output.directory = fullfile(pwd,'results','paper_actual_full_scan');
result = run_olg_experiment(cfg);
```

Параметры модели: `lambda=3.01`, `sigma=1.03`, `beta=0.99`. Сетка `b_L` теперь включает левую границу: **`1:0.0001:1.6`, 6001 узел**. Перебор начинается с 1. Ни граница `1/beta`, ни известная точка `1.54` не подсказывают DE направления поиска.

В обоих методах `Q=[0,1.3]×[0,2.1]`, шаг 10⁻⁴ по каждой координате, включая границы: **273 034 001 начальная точка**. Используется одна воспроизводимая shuffle-перестановка всей сетки: шесть раундов Фейстеля и cycle walking, без массива randperm(N). Хранятся только оси, таблицы степеней и текущие порции. Профиль demo не уменьшает разрешение Q.

### Два независимых выбора

```matlab
cfg = olg_config('compare_DE_vs_full_scan','paper','first_hit');
cfg = olg_config('compare_DE_vs_full_scan','paper','full');
```

Третий аргумент задаёт `cfg.search.phaseScan` и отдельный каталог режима. Он не связан с `cfg.search.gridMode`: `estimate` — измеренный DE и оценка стоимости сетки b_L; `full_scan` — реальный восходящий поиск по b_L. Выбор `full` для Q сам по себе не включает восходящий поиск параметра.

**first_hit:** первая порция 1280 узлов, затем 2560, 5120, 10240, 20480, 40960; далее по 40960. Число задач примерно сохраняется, их размер постепенно растёт. Это не бюджет Q: при отсутствии кандидата проверяются все 273034001 узел. После кандидата завершается запущенная порция. Сохраняется первый положительный узел в порядке обхода, а не ответ самого быстрого worker. Полная карта не записывается.

**full:** сразу используются большие порции. Для каждого b_L весь Q обрабатывается даже после кандидата, и результат каждого узла сохраняется на диск. DE прекращает поиск после завершения полного Q для первого положительного параметра. `ScreeningDeferred=0`. Диагностику можно явно отключить в новом каталоге, не меняя критерия кандидата.

```matlab
cfg.search.stateOrder = 'shuffle'; % Новый стандарт: Фейстель + cycle walking.
cfg.search.stateSeed = 20261026;
cfg.search.firstHitBatchSize = 1280;
% cfg.search.stateOrder = 'lex';      % C меняется быстрее L.
% cfg.search.stateOrder = 'permuted'; % Прежний аффинный обход.
```

Shuffle не хранит массив из 273 млн индексов, не меняет RNG оптимизатора и одинаков для всех b_L и повторений DE. Это псевдослучайный порядок без повторов, а не равномерный выбор из всех N! перестановок и не криптографический метод. Более ранняя находка на конкретном положительном b_L возможна, но не гарантирована; отрицательный результат по-прежнему требует полного Q.

Имена самостоятельного Q_MODES здесь сгруппированы: `phaseScan` → `search.phaseScan`, `phaseOrder/phaseSeed` → `search.stateOrder/stateSeed`, `firstHitBatchSize` → `search.firstHitBatchSize`, `integrator/zeroOneBackend` → `runtime.*`, `outputDir` → `output.directory`. Начинайте с нового `olg_config`; структуру самостоятельного эксперимента копировать нельзя.

### Критерий и остановка

В paper сохраняется окно **1000 transient + 4000 retained**: 0–1 получает `C_1001,...,C_5000`, 32 значения c и 400 лагов. Только после `K>=0.8` траектория продолжается до 10000. Розенштейн использует все `C_1,...,C_10000`; кандидат требует `LLE>=0.005` и `R²>=0.9`.

SALI и ConDN вычисляются **только после подтверждения** и не меняют fitness или остановку. Для диагностики SALI сохраняется 5000 шагов с нормировкой через 16 шагов; ConDN использует 100 нейронов и факторы `[1 2 4 8]`. Сокращения до 8 c или 24 нейронов нет. Повтор диагностической орбиты проверяется на совпадение с тем же backend и учитывается в затратах.

**Отрицательный результат требует полного обхода Q. При кандидате завершается уже запущенная порция, затем новые порции не запускаются.** Внутри worker после кандидата прекращаются новые вызовы индикаторов. Уже выполненные итерации всех траекторий порции входят в счётчики. Это поведение обновлённого fast-архива; для полного обхода и записи всех узлов выберите отдельный режим `full`, описанный ниже.

| Профиль | Короткий горизонт | Transient поиска | Ряд 0–1 | Ряд Розенштейна |
| --- | ---: | ---: | ---: | ---: |
| demo | 1000 | 100 | 900 | 2000 |
| paper | 5000 | 1000 | 4000 | 10000 |

Отрицательная координата останавливает траекторию сразу. Выход из Q сам по себе её не останавливает: Q задаёт только начальные состояния. Эвристический экран близости к периодической траектории из прежнего объединённого пакета в новом поиске не применяется.

### Настройки

```matlab
cfg.search.bRange = [1 1.6];
cfg.search.bStep = 1e-4;
cfg.search.includeLowerEndpoint = true;
cfg.search.Q = [0 1.3; 0 2.1];
cfg.search.stateStep = [1e-4 1e-4];
cfg.search.stateGridSize = [];       % Пусто: использовать stateStep.
cfg.search.stateChunkSize = 4096;
cfg.search.stateBatchSize = 40960;   % Кратно stateChunkSize.
cfg.search.repetitions = 5;
cfg.search.population = 20;
cfg.search.strategy = 7;            % DE/rand/1/bin из FEX.
cfg.search.mutation = 0.8;
cfg.search.crossover = 1;
cfg.search.cacheParameters = true;
cfg.search.diagnostics = true;
cfg.parallel.workers = 'auto';
```

Начальная популяция включена в стоимость. Повторные запросы завершённой отрицательной оценки используют кэш **внутри одного повторения**. `Evaluations` — все запросы, `UniqueEvaluations` — новые вычисления, `CacheHits` — попадания в кэш. У попадания нет новых траекторий, шагов или вызовов индикаторов. Между повторениями кэш не общий.

Для native-ускорения после сборки:

```matlab
cfg.runtime.integrator = 'native';
cfg.runtime.zeroOneBackend = 'native';
cfg.rosenstein.neighborMethod = 'native';
cfg.parallel.poolType = 'auto';
```

В R2024a MEX требует **Processes**; для полностью MATLAB-варианта используется **Threads**. Автоматический выбор workers ограничен физическими ядрами и числом chunks в порции. Таблицы передаются через `parallel.pool.Constant` один раз на параметр.

На длинных хаотических орбитах округление MATLAB и C++ может дать разные K/LLE и первую находку. Для сравнения обоих методов выбирайте одинаковые backend, chunks и порции. После изменения численных настроек используйте новый `cfg.output.directory`.

### Оценка стоимости сетки

В `estimate` измеряются начальные узлы и пробы нескольких диапазонов. Историческое предположение — находка при **b_L=1.5069, индекс 5070** на включающей 1 сетке. Это не установленная первая точка нового протокола. Флаги отчёта показывают, проверена ли она, подтверждена ли, найдены ли кандидаты ниже неё. Пробы не передаются DE.

`estimated_grid_cost.csv` содержит экстраполяции по начальному префиксу и по диапазонам. Отсутствие измерений диапазона даёт `NaN`. Детерминированные пробы не задают доверительный интервал и могут пропустить дорогой режим. Чтобы измерить первую находку восходящего поиска, используйте `full_scan`.

## Эксперимент 2

```matlab
cfg = olg_config('compare_chaos_indicators', 'paper');
result = run_olg_experiment(cfg);
```

Фиксированы `b_L=1.54`, `(C_0,L_0)=(0.5,1)` и те же `lambda,sigma,beta`. Общая MATLAB-орбита рассчитывается один раз до измерений. Transient не отбрасывается.

В paper 0–1, SALI и ConDN получают 5000 наблюдений; Розенштейн измеряется отдельно на **5000 и 10000**. В demo — соответственно 1000, а Розенштейн на 1000 и 2000. По вашему уточнению, сравнений FTLE по произведению якобианов в пакете нет.

Шесть строк отчёта: три индикатора, их сумма внутри каждого повторения, Розенштейн на коротком и длинном рядах. После полного прогрева выполняются семь последовательных повторений в фиксированном порядке, как в обновлённом timing-скрипте. Время общей орбиты вынесено отдельно.

По умолчанию `cfg.timing.implementation='optimized'`: объединённый cached FFT, нормировка SALI блоками по 16, разреженный пакетный ConDN, `trace` вместо SVD и исключение неиспользуемого обучения. Резервуар кэшируется при одинаковых настройках, в том числе после прогрева. Исходные размеры данных и резервуара сохраняются.

`cfg.timing.neighborMethod='brute'` сохраняет базовую линию предоставленного скрипта. Для отдельной проверки ускоренного точного дерева можно задать `'native'`; поисковый auto-backend не меняет этот параметр молча. Вариант `'reference'` позволяет проверить исходные индикаторы.

Для воспроизведения замеров ядер после сборки выполните `benchmark_olg_fast`: по умолчанию 1024 одинаковых узла Q и три повторения. Это сравнение ядер, а не полноразмерный поиск DE/сетки.

[Предоставленная таблица от 24 октября](example_results/optimized_timing_supplied_20261024/timing_summary.csv) включена с сохранением значений и исключением строк якобианного FTLE. Она отделена от новых проверочных запусков объединённого пакета.

## Карта для одного b_L без запуска DE

```matlab
cfg = olg_config('compare_DE_vs_full_scan','paper','full');
cfg.search.stateGridSize = [14 22]; % Явная проверка на 308 точках.
cfg.search.stateChunkSize = 32;
cfg.search.stateBatchSize = 64;
cfg.output.directory = fullfile(pwd,'results','map_check');
r = olg_scan_b(1.54,cfg);
preview = olg_plot_phase_map(r.basinFolder);
```

Для плотной сетки верните `stateGridSize=[]` и задайте новый каталог. Записи требуют **примерно 47*N байт до MAT-сжатия: 12,83 ГБ (11,95 GiB) на один b_L** для исходного Q, плюс метаданные. Полные карты для многих параметров требуют соответствующего места на диске. Траектории всех узлов целиком не хранятся. Повторный отрицательный b_L в одном DE-повторении использует прежнюю завершённую оценку и её карту.

В папке `*_basin` рядом с checkpoint находятся `metadata.mat` и `batch_*.mat`. Каждый batch хранит диапазон позиций `start/stop`, `scanId` и поля records:

| Поле | Тип | Содержание |
| --- | --- | --- |
| `id` | uint32 | Исходный декартов номер узла, независимо от shuffle |
| `status` | uint8 | Код исхода; см. `olg_phase_legend` |
| `attractor`, `period` | uint32, uint16 | Номер регулярного режима и найденный период |
| `steps` | uint32 | Итерации траектории без диагностического повтора |
| `last` | два double | Последнее состояние либо первое недопустимое |
| `K`, `LLE`, `SALI`, `ConDN` | single | Индикаторы; решение о кандидате ранее принимается в double |

Это **карта численных исходов на конечном горизонте**. Номера режимов присваиваются только регулярным хвостам: периоды до 32, последние max(64,8*p) наблюдений, допуск периодичности 1e-7 и сопоставления циклов в (C,L) 1e-5 с учётом фазы. Медленный транзиент может выглядеть регулярным, близкие режимы могут сливаться; устойчивость этим не доказывается.

У хаотических кандидатов **status=9, attractor=0**: они не объявляются одним общим хаотическим аттрактором. Код 11 объединяет выход из Pi, нечисловое состояние и safety stop во время подтверждения. Точный начальный нуль имеет status=1 и steps=0.

`olg_plot_phase_map` читает только закоммиченные записи, в том числе при незавершённом full. Лишние файлы от прерванной порции не учитываются. Для картинки выбираются не более 600×600 точных узлов; непосещённые остаются пустыми, метки не интерполируются. Полные записи обработанных узлов остаются на диске. Поддерживается чтение карт самостоятельного Q_MODES, но его checkpoint не переносится для продолжения расчёта.

Для одного параметра `firstCandidate.seconds` — время до возврата первой положительной порции. `phasePosition` — позиция кандидата в порядке обхода, `phaseIndex` — исходный декартов номер. В журналах/сводке поиска есть `FirstCandidateSearchSeconds` (также `FirstCandidateSeconds`), отдельно от `ElapsedSeconds`. В full второе включает завершение всей положительной карты. Первое время сохраняется при возобновлении. Оценка затрат grid-проб использует тот же режим Q и отражает полную стоимость выбранной процедуры.

## Сохранение и продолжение

Каталог `cfg.output.directory` теперь стабилен: **повтор того же вызова продолжает расчёт в нём**. Для нового независимого эксперимента задайте другой каталог. Создавайте свежую конфигурацию схемы 4; старые checkpoint несовместимы.

Прогресс Q сохраняется примерно каждые 30 секунд после завершённой порции. Журнал оптимизатора — после каждой оценки. При возобновлении состояние исходного DE восстанавливается детерминированным повтором сохранённых значений callback без новых траекторий. Незаконченная оценка продолжает Q с последнего checkpoint, в том числе full после уже найденного кандидата; незаписанная порция пересчитывается.

`FirstCandidateSeconds`/`FirstCandidateSearchSeconds` фиксируют первую вернувшуюся положительную порцию. В full оценка параметра заканчивается позже; её полная стоимость входит в `ElapsedSeconds`. Это не отдельная временная метка внутри worker.

`ElapsedSeconds` суммирует зафиксированную работу и управление оптимизатором, исключая создание пула и простой. Потерянная незаписанная работа при прерывании в этот таймер не восстанавливается. Worker-секунды этапов суммируются по параллельным вызовам и могут превышать wall-clock. Диагностические итерации модели и касательные шаги SALI учитываются отдельно.

```matlab
result = olg_show_results(cfg.output.directory); % Просмотр завершённого расчёта.
```

Сохраняются журналы, таблицы, MAT и PNG/FIG. В режиме оценки добавляются `actual_de_runs.csv`, `de_summary.csv`, `grid_probes.csv`, `estimated_grid_cost.csv`, `grid_cost_strata.csv`. В свидетеле хранятся C-ряд, диагностики и аппроксимация Розенштейна. Численный кандидат требует отдельного обоснования перед утверждением о хаотическом аттракторе и его бассейне.
