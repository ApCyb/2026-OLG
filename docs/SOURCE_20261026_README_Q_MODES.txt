Источник: самостоятельный olg_de_modes_experiment. Объединённый пакет использует FEX18593 DE и публичную конфигурацию olg_config.

OLG, эксперимент № 1: выбор полного обхода или поиска до кандидата
Версия 2026-10-26. Основная инструкция этого архива.

1. БЫСТРЫЙ ЗАПУСК

Распакуйте архив в НОВУЮ папку olg_de_modes_experiment и сделайте её
текущей папкой MATLAB. Не накладывайте файлы на прежнюю версию.

clear functions
addpath(pwd)
build_olg_fast
cfg = olg_modes_config('paper', 'first_hit');
cfg.integrator = 'native';
cfg.zeroOneBackend = 'native';
result = run_olg_modes_experiment(cfg);

Сборка нужна для обновлённого ядра интегрирования. В архиве также есть
готовые MEX для macOS Apple Silicon, собранные MATLAB R2024a.
На другой платформе соберите ядра build_olg_fast. Для полностью MATLAB-
варианта задайте integrator='matlab', zeroOneBackend='matlab',
rosenstein.neighborMethod='brute'. Переключение ядра меняет протокол:
длинные хаотические орбиты могут отличаться из-за округления.

По умолчанию: пять запусков DE; далее первые узлы и пробы диапазона
для ОЦЕНКИ затрат grid_lex. Это сохранённая постановка эксперимента № 1:
полный последовательный поиск по всем b_L НЕ заменён измеренными пробами
и НЕ выдаётся за выполненный. 5070 остаётся историческим предположением.
Порядок фазовых узлов одинаков для DE и всех проб b_L.

2. ДВА РЕЖИМА ОБРАБОТКИ Q ДЛЯ КАЖДОГО b_L

cfg = olg_modes_config('paper', 'first_hit');

Ищет первый численный хаотический кандидат. Остановка происходит после
завершения текущей параллельной порции. Уже запущенные задачи этой порции
могут завершить дополнительные траектории/проверки; всё это включено
в счётчики работы и время. Кандидат выбирается по первому положению
в заданном порядке обхода, а не по скорости ответа отдельного worker.
Внутри задачи проверки индикаторов прекращаются после кандидата.

ЕСЛИ КАНДИДАТА НЕТ, ПРОВЕРЯЕТСЯ ВЕСЬ Q: 273 034 001 УЗЕЛ.
Лимита числа фазовых точек, случайной подвыборки и скрытого отсечения нет.
Полная карта исходов в этом режиме не записывается.

cfg = olg_modes_config('paper', 'full');
cfg.integrator = 'native';
cfg.zeroOneBackend = 'native';
result = run_olg_modes_experiment(cfg);

Для каждого проверяемого b_L проходит весь Q, даже если кандидат уже
найден. Сохраняет результат каждого узла на диск. DE останавливается
после завершения полного Q для первого положительного b_L, как и раньше
останавливался после положительной оценки параметра.

Полный режим существенно дороже при положительном b_L: все выжившие
траектории проходят 0–1, все прошедшие порог проходят подтверждение,
все кандидаты — включённую диагностику SALI/ConDN.
Можно явно отключить только диагностику: cfg.diagnostics=false.
Это не изменяет критерий кандидата; используйте новый outputDir.

Конструктор создаёт разные папки results/q_modes/paper/first_hit и full.
При изменении иных настроек задавайте отдельный cfg.outputDir.
Старые контрольные точки FAST/STAGED несовместимы и не переносятся:
изменились порядок узлов, порции, содержимое результатов и подпись протокола.

3. ОБХОД БЕЗ МАССИВА ИЗ 273 МИЛЛИОНОВ НОМЕРОВ

cfg.phaseOrder = 'shuffle';       % новый стандарт
cfg.phaseSeed = 20261026;         % фиксирует порядок фазовых узлов

Псевдослучайная перестановка всех номеров узлов без повторов.
Используется обратимая шестираундовая сеть Фейстеля и cycle walking:
перестановка на степени четвёрки ограничивается диапазоном 0,...,N-1.
Хранится только текущая порция, а не randperm(N).
Порядок воспроизводится по seed, не меняет генератор случайных чисел DE
и не зависит от b_L или номера повторения DE. Пять DE-запусков имеют
свои разные optimizer seeds при общем порядке начальных состояний.

Это псевдослучайное рассеивание соседних позиций по Q, а не гарантия
равномерного выбора из всех N! перестановок и не криптографический метод.
Каждый узел встречается ровно один раз в полном проходе.

Другие варианты для сопоставления:
cfg.phaseOrder = 'lex';          % C меняется быстрее L
cfg.phaseOrder = 'permuted';     % прежний аффинный обход с фиксированным шагом

Ранее уже был аффинный обход, а не обычный проход строками. Новая
перестановка убирает его постоянный арифметический шаг. Она может раньше
попасть в область положительных кандидатов, но ускорение на любом b_L
не гарантировано. Отрицательный результат требует того же полного Q.

first_hit начинает с cfg.firstHitBatchSize=1280 узлов, затем 2560,
5120, 10240, 20480, 40960; далее порции по cfg.phaseBatchSize=40960.
Число независимых задач сохраняется примерно постоянным, размеры задач
растут до cfg.phaseChunkSize=4096. В full сразу используются большие порции.
Можно менять firstHitBatchSize до запуска. Это размер первой порции,
а НЕ лимит обработки Q. Для smoke используются меньшие размеры.

4. КАРТА ДЛЯ ОДНОГО b_L БЕЗ ЗАПУСКА ВСЕГО DE

cfg = olg_modes_config('paper', 'full');
cfg.integrator = 'native';
cfg.zeroOneBackend = 'native';
r = olg_scan_b(1.54, cfg);
preview = olg_plot_phase_map(r.basinFolder);

Этот вызов проходит весь Q при b_L=1.54. Можно сначала выбрать smoke
вместо paper для проверки функций на 308 узлах с шагом 0.1.

Для отдельного быстрого поиска свидетеля:
cfg = olg_modes_config('paper', 'first_hit');
cfg.integrator = 'native';
cfg.zeroOneBackend = 'native';
r = olg_scan_b(1.54, cfg);

В полном режиме evaluation_XXXXXX_basin рядом с контрольной точкой
содержит metadata.mat и batch_*.mat. Для olg_scan_b имя evaluation_basin.
У каждого batch-файла есть start/stop (позиции обхода), scanId и records:
 id         uint32: исходный номер в обычной декартовой сетке;
 status     uint8: код исхода, см. olg_phase_legend;
 attractor  uint32: номер численно сопоставленного РЕГУЛЯРНОГО режима;
 period     uint16: найденный период (1 для равновесия);
 steps      uint32: число шагов траектории, без повторной диагностики;
 last       double, два столбца: последнее состояние/первое недопустимое;
 K, LLE     single: 0–1 и оценка Розенштейна;
 SALI,ConDN single: диагностика кандидата (NaN, если не вычислена/неуспешна).

Решение о кандидате принимается в double до округления значений в records.
Точные индикаторы свидетеля и его траектория остаются в контрольной точке.
Для code=11 подробная причина подтверждения не разделена: выход из Pi,
нечисловое состояние или превышение safety limit. Для steps=0,status=1
исходное состояние — точный нуль, известная неподвижная точка.

Восстановление координат любого сохранённого узла:
id = double(records.id);
C0 = Q(1,1) + mod(id-1,13001)*1e-4;
L0 = Q(2,1) + floor((id-1)/13001)*1e-4;
Для иной сетки используйте grid.size(1), grid.Q и grid.step из metadata.mat.

Все массивы записей требуют около 47*N байт до MAT-сжатия:
12.83 GB (11.95 GiB) на ОДИН b_L при исходном Q, плюс метаданные.
Фактический размер зависит от сжимаемости. Запись полного Q для многих
параметров требует соответственно большого дискового пространства.
Траектории всех узлов целиком не хранятся. Совпадающий отрицательный b_L
в одной DE-попытке использует прежний результат и прежнюю папку карты.

olg_plot_phase_map читает только завершённые порции, в том числе при
незаконченном расчёте. Укажите путь к папке *_basin, если переменной r
после Ctrl+C ещё нет. Для изображения выбираются до 600x600 точных узлов
исходной сетки; пропущенные/непосещённые точки не интерполируются.
Все обработанные узлы остаются в batch-файлах с полным шагом 1e-4.
Файлы phase_map.png и phase_map_preview.mat создаются без пересчёта орбит.

5. ЧТО ОЗНАЧАЕТ «КАРТА БАССЕЙНОВ» В ЭТОМ РАСЧЁТЕ

Сохраняется карта ЧИСЛЕННЫХ ИСХОДОВ на конечном горизонте.
Только регулярные хвосты сопоставляются по отдельным номерам режимов.
Проверяются периоды 1,...,basinMaxPeriod=32 на последних max(64,8*p)
наблюдениях первого этапа. Порог basinPeriodTol=1e-7 масштабируется
по амплитуде. Представители циклов сопоставляются в (C,L) с порогом
basinClusterTol=1e-5, с точностью до фазы цикла.

Это приближение: медленный транзиент может выглядеть регулярным,
период больше 32 останется неразрешённым, близкие режимы могут сливаться
в пределах заданного допуска. Метка не доказывает устойчивость цикла.

Хаотические кандидаты имеют status=9, attractor=0. Они НЕ объявляются
одним общим хаотическим аттрактором. Для разделения нескольких
хаотических аттракторов нужны дополнительное сравнение их орбит/мер
и проверка сходимости при увеличении горизонта. Пока эта часть карты
явно обозначена как «chaos candidate (attractor identity unresolved)».

6. ИНДИКАТОРЫ И ВРЕМЯ

Прежние настройки сохранены: 1000 transient + 4000 retained, FFT 0–1
по 32 значениям c и 400 лагам; при прохождении KThreshold — продолжение
той же траектории до 10000 и Розенштейн. SALI и ConDN остаются
диагностикой, не меняют критерий кандидата. ConDN: 100 нейронов.

firstCandidate.seconds — время до возврата первой положительной порции
данного b_L, а не недоступная точная временная отметка внутри worker.
firstCandidate.phasePosition — позиция первого кандидата в порядке обхода;
phaseIndex — исходный декартов номер. trajectories включает все начатые
траектории порции, даже если часть индикаторов после находки не нужна.
screeningDeferred показывает число таких пропущенных проверок выживших
траекторий; в full оно равно нулю.

В de_XX.csv и actual_de_runs.csv есть firstCandidateSearchSeconds.
В full оно отделено от searchSeconds: второе включает завершение карты
положительного b_L. Поэтому сравнивать first_hit и full только по старому
searchSeconds как по времени обнаружения кандидата нельзя.
В de_summary.csv добавлено meanFirstCandidateSearchSecondsSuccessfulOnly.
Оценки grid_lex используют тот же выбранный режим обработки Q.
Время первого кандидата возвращается по завершении полной оценки в full;
в незавершённом full оно доступно как s.firstCandidate в checkpoint.

Пул выбирает число физических ядер, но не больше числа задач в порции.
Native использует Processes (ограничение R2024a); cfg.workers='auto'
и cfg.resizePool=true оставлены в конфигурации. Время запуска пула
не включается в searchSeconds.

7. ПРЕРЫВАНИЕ И ПРОДОЛЖЕНИЕ

После Ctrl+C повторите тот же вызов с тем же cfg и cfg.resume=true
(это стандарт). В first_hit сохранение происходит периодически и после
положительной/последней порции. В full — после каждой порции записей.
Последняя незакоммиченная работа будет повторена. Отдельно записанные,
но ещё не подтверждённые checkpoint файлы не учитываются при чтении карты.
Изменение режима, порядка, seed сетки, индикаторов или размеров порций
требует новой папки результатов. Число workers можно менять.
