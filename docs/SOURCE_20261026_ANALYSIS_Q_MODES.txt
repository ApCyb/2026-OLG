2. Что действительно меняет новая версия.

а) Явный выбор phaseScan=first_hit/full вместо неявной постоянной
остановки на кандидате. В full сохраняется карта всех исходов по узлам.

б) Псевдослучайный порядок вместо прежнего аффинного шага. Нет повторов,
не выделяется массив randperm(273034001). Для хранения такого массива
double потребовалось бы около 2.18 GB дополнительно. Новая генерация
требует памяти только на текущую порцию плюс небольшие ключи.

в) Первая порция 1280 вместо 40960, далее удвоение до 40960. На удачном
b_L уменьшается число траекторий, уже запущенных до обнаружения кандидата.
На отрицательном b_L сохраняется пропускная способность больших порций
после короткого разгона. Небольшая дополнительная стоимость генерации
перестановки не означает сокращения полного отрицательного прохода.

г) Полная запись исходов порциями, без хранения полной карты/всех
траекторий в оперативной памяти. По каждому b_L создаётся отдельная
папка карты. Старые результаты не перезаписываются новым протоколом.

3. Чего нельзя заключить заранее.

Перестановка не гарантирует более раннюю находку по сравнению с любой
другой перестановкой для конкретного бассейна. Эффект необходимо измерять
по времени, числу проверенных начальных состояний и числу индикаторных
вызовов, при одинаковых b_L, ядре, порогах и вычислительном окружении.

Если b_L не даёт кандидатов, каждый из 273034001 узлов всё равно нужен
для принятой процедуры. Одновременно обеспечить исчерпывающий
отрицательный ответ и почти мгновенный переход к следующему b_L
перемешиванием невозможно. Пользователь явно выбрал отсутствие лимита;
никаких ограничений бюджета Q, аналитических пропусков области b_L
или подмены полного Q выборкой в реализации нет.

Наличие численного кандидата не доказывает существование аттрактора
или бесконечную допустимость его траектории. Отсутствие кандидата на всей
конечной сетке также не исключает хаос между узлами либо при другом
горизонте/критерии. Метки регулярных хвостов — приближение к бассейнам.

4. Практическое разделение задач.

Для сравнения быстроты обнаружения: first_hit, одинаковый phaseSeed
для DE и grid-проб, пять разных seeds DE. При найденном b_L отдельно
выполнить olg_scan_b(b_L, конфигурация full) для карты исходов.
Это экономит полные положительные карты на всех промежуточных шагах
поиска. Отрицательные оценки остаются исчерпывающими по решению пользователя.

Для изучения бассейнов при заранее выбранных b_L: полный olg_scan_b,
затем olg_plot_phase_map. Поиск и картирование имеют разные конечные
продукты и должны иметь отдельные показатели времени.

Если успех происходит уже в начальной популяции DE, это преимущество
случайной инициализации перед восходящей сеткой, а не свидетельство
работы мутации/скрещивания. В отчёте сохранена candidateInInitialization.
Пять запусков и оценки grid по пробам дают предварительное сопоставление,
а не доказательство универсального преимущества DE.

5. Основание механизма перестановки.

Cycle walking ограничивает обратимую перестановку большего конечного
множества подмножеством без потери взаимно-однозначности. Описание:
J. Black, P. Rogaway, “Ciphers with Arbitrary Finite Domains”:
https://www.cs.ucdavis.edu/~rogaway/papers/subset.pdf

Используемая здесь функция смешивания предназначена для порядка обхода,
не является шифром и не наследует доказательства криптографической
случайности из указанной работы. Обратимость сети Фейстеля не требует
обратимости её внутренней функции смешивания. Циклический проход
возвращает следующий элемент допустимого подмножества в том же цикле;
поэтому пропусков и повторов в полном обходе нет.
