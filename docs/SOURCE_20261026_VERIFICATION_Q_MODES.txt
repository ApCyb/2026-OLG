Источник: самостоятельный olg_de_modes_experiment. Объединённый пакет использует FEX18593 DE и публичную конфигурацию olg_config.

ПРОВЕРКА ВЕРСИИ 2026-10-26

Среда: MATLAB R2024a, macOS Apple Silicon. Ядра пересобраны Xcode Clang++.
Главная проверка: tests/test_olg_modes.m; итог PASS.
Журнал успешной проверки включён в verification/matlab_tests.log архива.

Проверено:
- Все узлы перестановки для N=1,2,3,4,37,308,1025,10000 встречаются
  ровно по одному разу, в пределах диапазона.
- Первые 100000 номеров реального Q из 273034001: нет повторов,
  координаты в Q; одинаковый seed воспроизводит порядок, другой меняет;
  формирование сетки не меняет RNG оптимизатора.
- Генерация этих 100000 точек: 0.0974 s в проверочном запуске.
  Это один локальный замер, не оценка всего эксперимента.
- Детали интегратора (выход/нулевая точка/шаги) совпадают для MATLAB
  и native; короткие траектории совпадают с точностью 1e-8.
- Регулярные циклы сопоставляются с точностью до фазы, а разные периоды
  получают отдельные номера.
- Q=[0,1.3]x[0,2.1], h=0.1: 308 точек; lambda=3.01,sigma=1.03,
  beta=0.99,b_L=1.54. Горизонты не сокращены: 1000+4000,10000.
  first_hit: 16 обработанных узлов, найден кандидат.
  full: 308 записей без дубликатов, 108 кандидатов; ни один выживший
  узел не оставлен без классификации, screeningDeferred=0.
- Диагностика свидетеля выполнена на воспроизведённой той же орбите.
- Все хаотические кандидаты имеют attractor=0, т.е. не объединены
  в один якобы установленный аттрактор.
- Построение карты читает сохранённые записи, без расчёта траекторий.
- Завершённый checkpoint возвращает прежнее время/счётчики без работы.
- Регрессионная проверка full-checkpoint с candidate=true и оставшимися
  узлами: обход продолжается. После искусственного изменения состояния
  тест заново формирует согласованный полный результат.
- Отрицательный b_L на маленькой сетке проверяет все узлы без лимита.
- Несовместимое изменение порядка блокирует загрузку checkpoint.
- Полный режим работает с MATLAB- и native-интегратором.
- На двух Processes workers full даёт то же число кандидатов и те же
  количества меток, что последовательный native-проход.
- Короткий end-to-end эксперимент: один DE-повтор, измеренные grid-пробы,
  CSV, отчёт, PNG. Добавленная колонка первого обнаружения конечна.
  Найден кандидат уже в инициализации — тест не доказывает преимущества
  эволюционных операций DE.

Примерные времена в одном запуске (не бенчмарк):
 first_hit, последовательно: 0.367 s;
 full, последовательно: 4.009 s (повторный новый проход 3.796 s);
 full, два worker: 2.922 s, без запуска пула.
Данные служат проверке поведения режимов; нельзя переносить отношение
времён с h=0.1 на 273034001 узел с h=1e-4.

После тестов отдельно проверен экспорт карты: уникальные цвета кодов,
читаемые подписи, целочисленные номера регулярных режимов. Исправлена
семантика meanSecondsToCandidateSuccessfulOnly: время до возврата
первой положительной порции, а не до завершения полной карты.
Прочие столбцы searchSeconds сохраняют стоимость всего выбранного режима.

Основной опыт с 273034001 узлом на каждый b_L НЕ запускался.
Карта/лог примера в verification относятся только к уменьшенной сетке.
Старые контрольные точки FAST/STAGED не используются в новой версии.
